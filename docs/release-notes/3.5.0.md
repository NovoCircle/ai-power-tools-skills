AI Power Tools for Sparx EA 3.5.0.

**The server and the skills now ship as one plugin, on one version.** Installing is one command, updating is one command, and there is one number to reason about instead of three.

## Installing

```
claude plugin marketplace add NovoCircle/ai-power-tools-skills
claude plugin install ai-power-tools@novocircle
```

Restart Claude afterwards — plugin changes are staged, not applied to a running session.

That brings the skills **and** the MCP server, on every surface: the CLI, the desktop Code tab, VS Code, Claude Desktop chat and Cowork. Plugins are the only mechanism all of them load.

Enterprise Architect still has to be installed on the same Windows machine. The server drives EA over COM, so it runs where EA runs — a Cowork session in the cloud reaches it through Claude Desktop on your workstation, which relocates the conversation, not EA.

## What changed, and why

Until now the skills and the server were two artifacts from two repositories, versioned separately with nothing linking them, delivered through three different channels. That produced problems no customer should have had to work around: no way to discover the plugin, duplicate skills on any machine that tried both, and a version floor that one channel enforced and the other ignored.

One plugin removes all of it. The plugin declares the server by a **pinned** release URL, so one plugin version maps to exactly one server build — a later server release cannot silently change what an already-installed plugin loads.

### One version

The skills, the MCP server and the VS Code extension are all 3.5.0 and ship together. The binary will sometimes be byte-identical between versions, because a skills-only change still bumps the number. That is the cost of one version, and it is cheaper than explaining three.

## If you installed skills with `install_skills`

Before 3.5.0 the skills arrived through the `install_skills` MCP tool, which copied them into `~/.claude/skills`. The plugin supersedes that.

`install_skills` now **declines** rather than writing a second copy. The two are additive: a machine carrying both loads every skill twice — once unprefixed, once as `ai-power-tools:<name>` — because they are different sources and nothing deduplicates across them. That is double the always-on token cost, and it leaves it ambiguous which copy answers.

To clear the older copies, download **`migrate-to-plugin.ps1`** from the [server release](https://github.com/NovoCircle/ai-power-tools-releases/releases/latest) and run it:

```powershell
.\migrate-to-plugin.ps1 -WhatIf     # show what would go, change nothing
.\migrate-to-plugin.ps1             # list it, then ask before removing
```

It prints the skills it would remove, names the ones it will **not** touch, and deletes nothing until you type `YES`.

**Do not delete `~/.claude/skills` by hand.** It may also hold skills for AI Power Tools for Microsoft Visio — a separate product with its own installer — and any skills you wrote yourself. The script can tell them apart because it reads the installer's own record of what it wrote; a directory listing cannot. Anything you edited locally is copied to a backup before removal and named in the summary.

This is a one-time job, which is why it ships as a downloadable script rather than living in the product and costing every session tokens for something almost nobody will run.

## Enterprise deployment

For a managed fleet, declare the marketplace and the plugin in the admin-controlled settings source and every machine picks it up with no user action.

Windows, either of:

- the `HKLM\SOFTWARE\Policies\ClaudeCode` registry key
- `C:\Program Files\ClaudeCode\managed-settings.json`

macOS and Linux: `/etc/claude-code/managed-settings.json`

```json
{
  "extraKnownMarketplaces": {
    "novocircle": {
      "source": {
        "source": "github",
        "repo": "NovoCircle/ai-power-tools-skills",
        "ref": "v3.5.0"
      }
    }
  },
  "enabledPlugins": {
    "ai-power-tools@novocircle": true
  }
}
```

Two things to know:

- A marketplace on a network location **must** be declared in user or managed settings. Project and local scope are refused for network sources, so managed settings is the correct admin-trusted home.
- `ref` pins the fleet to a git ref. Pin it wherever an unreviewed change would be unwelcome; omit it to track the default branch.

Full detail in `docs/enterprise-deployment.md`.

## Fixes

- **The server would not start when delivered by a plugin.** Its MCPB manifest declared no `args`, and the plugin loader spreads that field — an undefined spread, so the server never launched. Only the plugin path was affected; installing the same `.mcpb` as a Claude Desktop extension always worked.
- **The release gate reported GREEN when one of its checks had not run.** Its operation-drift check resolved the server source relative to the repository, which misses from inside a git worktree. It printed a warning and passed anyway, so a worktree-based release shipped without the check that catches skills naming operations the binary does not have.

## Verifying an install

```
claude plugin list
claude plugin details ai-power-tools
```

Expect `ai-power-tools@novocircle` enabled at 3.5.0, with the skills listed and the MCP server present. `_shared` is correctly not among the skills — it carries no `SKILL.md` and ships only so the skills' relative links resolve.
