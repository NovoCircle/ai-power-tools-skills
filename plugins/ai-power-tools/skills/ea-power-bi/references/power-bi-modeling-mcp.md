# Microsoft's Power BI Modeling MCP server

Microsoft publishes its own MCP server for reading and editing Power BI semantic models. **It is
Microsoft's product. The customer installs it, Microsoft's license agreement governs it, and AI
Power Tools does not ship or support it.** It runs as a local stdio server, so any Claude client that
runs local MCP servers can use it, not only Visual Studio Code. It is optional: nothing in
`ea-power-bi` depends on it.

Use it when a customer asks to look inside a generated project - list its tables, relationships or
measures - from the assistant, or to run a DAX query against a model.

## Where it comes from

Either route gives the same server (`powerbi-authoring-local`).

- **The Power BI Authoring MCP extension for Visual Studio Code.** After the install, the server is
  `%USERPROFILE%\.vscode\extensions\analysis-services.powerbi-modeling-mcp-<version>-win32-x64\server\powerbi-modeling-mcp.exe`.
- **The npm package `@microsoft/powerbi-modeling-mcp`,** run with `npx`. Node.js is required.

Microsoft's page: `https://github.com/microsoft/powerbi-modeling-mcp`.

## Accept the license agreement first

The server blocks every other tool call until Microsoft's agreement is accepted. The customer reads
it, then accepts it one of three ways:

- set the environment variable `PBI_MODELING_MCP_ACCEPT_EULA` to `true`
- add `--accepteula` to the server's arguments (the executable also takes `--accept-eula`)
- in an interactive session, authorize the assistant to call the server's `accept_eula` tool

Never accept on the customer's behalf without their say-so.

## Register it with Claude Code

```
claude mcp add --transport stdio --env PBI_MODELING_MCP_ACCEPT_EULA=true powerbi-authoring-local -- npx -y @microsoft/powerbi-modeling-mcp@latest --start --readonly
```

For the extension's file, replace `npx -y @microsoft/powerbi-modeling-mcp@latest` with the full path
to `powerbi-modeling-mcp.exe`. Add `--scope user` to make it available in every project.

## Register it with Claude Desktop

Add this entry to `mcpServers` in `%APPDATA%\Claude\claude_desktop_config.json`, then quit and
restart Claude Desktop:

```json
"powerbi-authoring-local": {
  "command": "npx",
  "args": ["-y", "@microsoft/powerbi-modeling-mcp@latest", "--start", "--readonly"],
  "env": { "PBI_MODELING_MCP_ACCEPT_EULA": "true" }
}
```

For the extension's file, set `command` to the full path of `powerbi-modeling-mcp.exe` (backslashes
doubled in JSON) and drop `-y` and the package name from `args`.

## Flags worth knowing

| Flag | Effect |
|---|---|
| `--start` | Starts the server. Required |
| `--readonly` | Blocks every write to the semantic model. **Recommend it for inspection** |
| `--readwrite` | The default. Allows writes |
| `--require-confirmation` | Asks for confirmation before each write. Microsoft's README and the executable's `--help` describe the default confirmation differently, so add this flag when the customer wants prompts |
| `--accepteula` | Accepts the license agreement for this run |

`--help` on the executable lists the rest (`--authmode`, `--compatibility`, `--audit-log-path`).

## What it connects to

The target is named in the conversation:

- a model open in Power BI Desktop, by file name
- a semantic model in a Fabric workspace, by model name and workspace name
- a Power BI project, by the semantic model's `definition` folder (`connection_operations`,
  operation `ConnectFolder`)

## Worked example: list the relationships of a generated project

Customer's words, with their own project:

> Open the semantic model from the Power BI project folder
> `<project-folder>\<project-name>.SemanticModel\definition`, then list its relationships.

The assistant calls `connection_operations` (`ConnectFolder`), then `relationship_operations`
(`List`); `model_operations` (`Get`) and `table_operations` (`List`) answer in the same way. Each
relationship comes back with its two tables and columns, direction, cardinality and active state.
Compare the count with the one the generator printed.

Measured with server version 1.0.0 (stdio, from the extension's executable) on a Westbrook Bank
project generated by this skill: 51 tables, 51 measures and 83 relationships loaded. The figures
belong to that one model; they show the shape of a result, not what a customer will see.

## Changes are held in memory

A model loaded from a folder lives in the server's memory. An edit made through the server is not on
disk until the model is exported to a TMDL folder (`ExportToTmdlFolder`), and the server warns of
this on load. The generated project stays the source of truth: the next generation rewrites the
semantic model's definition and discards edits exported into it. Under `--readonly` nothing changes.
